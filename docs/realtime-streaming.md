# 流式双语字幕实施记录

日期：2026-11-06。本地代码交付，尚未部署。

## 使用

在「实时翻译」中取消「仅转文字」，选择 DeepSeek Flash 或 GLM 5.3 Flash 后开始收音。
默认 Whisper 在浏览器内转写；识别文字发送到所选翻译服务，翻译请求关闭思考。
供应商配置见 [模型供应商配置](model-providers.md)。当前语段显示可修订的译文草稿，句末进入「字幕记录」。记录中的状态明确区分：
等待翻译、正在生成、已确认和未完成。失败的语段保留原文及可见草稿，可单段或批量重试。

暂停会整理已采集音频并确认语段。结束会先关闭麦克风，再处理剩余音频和译文；排队数量显示在界面。
字幕只保存在页面内存中，离开页面会取消任务并释放资源。

移动触控设备继续默认 CPU；PC 自动优先 GPU。布局沿用单列/双列响应式，按钮触控区域至少 44px。
这说明代码适配方式，不表示真实手机的麦克风、推理速度或持续负载已完成验收。

## 已实现

- 识别与翻译独立串行消费。正常范围内，慢译文不挡住下一窗 ASR。
- 每句独立 ID，源文快照修订、翻译生成修订和请求 ID 分别记录；迟到回调不能覆盖新句或新版本。
- 一个在途翻译请求，同一句一个最新待处理草稿；草稿间隔 1050ms，定时执行最后一次更新。
- 句末任务优先且按序保留；源文已经结束时先保存字幕记录，译文随后更新。
- 静音/停止、句末标点、20 秒或 1200 字符上限整理语段。过长源文切段保留全部余文。
- 上下文在开始翻译时读取，只带本句之前最多 8 条源文，只有已确认译文进入双语上下文。
- 翻译失败独立标在句段上，不打断本机转写；积压达到 12 个句末任务时暂停收音并提示，避免无界请求。
- 客户端 POST + SSE，服务端 DeepSeek / GLM `stream: true`；重试重置本轮累积器，保留上一份有效草稿，异常 EOF、截断和空结果不确认。
- 客户端 30 秒、服务端 28 秒单次超时，现有最多 2 次退避重试；取消释放 reader 并中止上游。

源文稳定前缀使用相邻窗口相同前缀启发式；译文依然允许整句替换。没有模型注意力接口，也不把 token 流
等同于已经实现词级同时翻译。Whisper 仍先完成一个音频窗的识别，现有最大窗口为 6 秒。

## 协议

请求正文保留 sourceText、sourceLanguage、targetLanguage、stage、sequence、revision、上下文，
`model` 指定 `deepseek` 或 `glm`，真实模型名及 Key 由服务端解析，默认 DeepSeek；
新增 utteranceId 与 requestId。客户端每次重试对逻辑 requestId 增加 attempt 后缀。

每个响应事件回显 `{utteranceId, requestId, sequence, revision, stage}`：

| type | 内容 | 语义 |
| --- | --- | --- |
| start | 身份字段 | 开始当前请求 |
| delta | delta、offset | 追加本轮新文本；offset 为累计 UTF-16 长度，用于重复/缺口检查 |
| final | text | 本轮完整有效结果；只有 confirmed 任务才能标记为句末确认 |
| error | code、message | 本轮失败，保留原文供重试 |

Provider 的 onDelta 回调提供**本轮累计文本**，便于将来接 Worker 消息；每次重试前 onReset('generation')
重置本轮累积器，上一份有效草稿仍可见，新文本从头替换；onReset('invalid') 丢弃本轮无效文本。
源文更新后新请求可替换整条译文。客户端保留旧 JSON 端点的读取兼容，方便前后端分步更新；旧端点不会提供 token 流。

## 代码入口

- `src/services/realtime/session.ts`：语段、识别消费、字幕更新、失败重试与生命周期。
- `src/services/realtime/translationScheduler.ts`：翻译串行消费、最新草稿、句末队列、取消和末次节流。
- `src/api/realtimeClient.ts`、`eventStream.ts`：身份校验、流解析、超时、重试与取消。
- `cloud-functions/api/realtime/translate.js`、`translationStream.mjs`：上游流与本站 SSE 中继。
- `src/components/RealtimeTranslation/RealtimeTranslation.tsx`：响应式字幕、状态与重试。

## 本轮检查与边界

已执行 TypeScript 项目检查、Whisper 静态资源准备、Vite 生产构建与 oxlint，均通过；构建仍有既有的大包提示。
本轮未新增或执行自动测试；既有实时 handler 测试的响应预期同步为 SSE。

独立只读代码审阅发现并修复了三项边界问题：取消启动期间界面设置与引擎不同步、旧暂停操作影响恢复后的语段、
重试抹掉有效草稿。另补充了重试旧句时保留当前句草稿的调度逻辑。修复通过静态追踪和类型/构建检查，
没有把它描述成已经执行过运行回归。

本机没有 `.env.local` 中的真实 MiMo 配置，因此未对真实翻译上游做端到端调用；也没有做新的浏览器麦克风
联调或 iOS/Android 真机验收。此前 Whisper 推理和手机尺寸模拟的证据保留在
[STT 检查记录](research/2026-11-06-stt-verification.md)，不能作为本轮流式字幕的运行验收。

后续运行验收应覆盖慢翻译下持续收音、语段结束附近的原文修订、断流/截断/429、停止与重试、
中英互译和连续课堂语料。真实手机需检查授权、前后台切换、内存、发热与长时间运行。

本轮没有推送或部署。在线 API 仍需服务端 MIMO_API_KEY；本机仅转文字可沿用已加载的模型缓存离线工作。
TTS 语音播报和纯浏览器文字翻译模型未在本轮接入。
