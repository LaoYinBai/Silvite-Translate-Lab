# 翻译完成后的自动分段中英对照

2026-11-07。翻译结果默认显示完整译文，在后台生成“分段中英对照”。仅对 `zh → en` 或 `en → zh` 启用，兼容 `zh-CN` / `en-US` 等语言代码。

## 数据与生命周期

- 普通文字和文档使用发起本次翻译时的原文快照；结果生成后修改输入框不改变旧结果的原文。
- 图片只有在响应含有实际识别原文时才有材料可对照；当前扫描 PDF 聚合结果没有完整识别原文时不伪造对应。
- 长文流程在每个确认请求、超时拆分后的成功请求和代码块直通时记录两侧字符范围。失败或取消的请求不生成锚点。
- 成品译文先显示，再启动对齐 Worker。新建翻译、重译或切换演示会取消旧任务；对齐失败仍保留完整译文，结果不改成翻译失败。

## 对应方法与边界

从原始字符串划分段落，再按句号、问号、感叹号等自然句界分段。中文超过约 70 个可见字符、英文超过约 240 个可见字符的长句尝试在逗号、分号、冒号或破折号等处形成可读片段，避开数字分隔、引号和括号内部；不在任意字数处硬切。代码围栏块保持完整。保存原始 UTF-16 范围，保留分隔空白，不重写原文或译文。

先用已确认的长文请求边界约束对应区间；请求切在段落中间时不把该边界当作完整段落锚点。区间内以长度比例、数字一致性和顺序做有界动态规划，支持 1:1、1:N、N:1、N:M（自动每侧最多 3 段）和单侧未匹配。该思路采用基于长度线索的对齐方法，参考 [Gale 与 Church 的原论文](https://aclanthology.org/J93-1004/)，本实现是独立的段落启发式，并未复现该论文的概率模型。

本地对应提供结构建议；不会为了凑齐两侧片段数量而合成长于可读上限的整段，未匹配内容保留供核对。字符计数预先计算，选取分句边界不反复遍历剩余全文。

出现长句、拆合或较弱对应时，在原文与译文合计不超过 12,000 字符、本地对应不超过 160 行的范围内，使用当前选择的 DeepSeek / GLM 做一次后台辅助请求。`POST /api/alignment` 复用已有服务端配置，不向前端暴露 Key；关闭 thinking。AI 只能复制已有文本并提出配对，不能改写、补译或执行材料中的指令。服务端将结果转为原文偏移，浏览器再次验证两侧顺序、完整覆盖和 Unicode 边界。仅外层 JSON 围栏可移除；截断、改写、漏字或无效响应被拒绝。

AI 最多生成 256 行，服务端超时 75 秒、客户端 85 秒，默认每 IP 每分钟 6 次。超出辅助范围、失败、限流或校验不通过时保留本地结果；用户可重试或到语料工具人工校正。AI 对应也不等于人工确认，不宣称可发现所有漏译、换序或错译。

两侧原文字符必须各覆盖一次；覆盖不完整时退出对照并保留完整译文。大规模行数或无法建立有界路径时，两侧段落均单独保留为未匹配。计算在 Worker，限制动态规划搜索带宽；20 秒未完成则释放 Worker 并保留完整译文。

## 界面与导出

- 默认显示“完整译文”，可切换“分段中英对照”；分段可晚于译文完成。后台更新不会切换用户当前视图。桌面两列，手机每组先原文后译文。
- 每页最多显示 40 组，长文本通过分页查看，所有组均保留在结果数据中。
- 复制和 PDF / Word / Markdown 继续只使用 `result.translation`；翻译说明仍由现有导出选项控制。
- “制作 TMX / RTF 语料”沿用当前分段对应的原文范围，可继续编辑、复核和导出；分段未完成时该操作等待，不擅自另取尚未完成的版本。

不添加依赖。辅助分段会使用所选模型并产生额外请求；大文本和无需辅助的结果使用本地规则。代码入口在 `src/services/alignment/`、`cloud-functions/api/alignment*`、翻译 store 和结果组件。

## 线上故障与复验（2026-11-07）

截图中的“AI 辅助分段暂未完成”表示 AI 请求失败后，界面保留了本地规则结果；本地算法的 12 组中有 3 组未匹配，所以这些内容显示为未找到对应。线上复现发现 EdgeOne 请求可能没有 `Request.signal`，旧处理器在调用模型前因此崩溃；随后还发现对齐接口自建的 `request.body.getReader()` 在 EdgeOne 请求流上读取失败。已改为可选 signal 和平台支持的 `request.text()`，并区分请求体、JSON、模型完成状态及原文校验错误。

DeepSeek Flash 曾返回可解析 JSON，但不符合行字段约定。现在 DeepSeek 请求显式使用 JSON Output，并明确要求 `pairs[].source` 对应 `source_text`、`pairs[].target` 对应 `target_text`；服务端仍逐字校验，不完整或改写的输出不会被采用。JSON Output 仅约束 JSON 语法，详见 [DeepSeek JSON Output 文档](https://api-docs.deepseek.com/guides/json_mode/)。

实发线上 DeepSeek 样文复验：HTTP 200，返回 8 组 AI 对齐；中文原文 374/374 字符、英文译文 1697/1697 字符均完整覆盖。样文为本项目生成的虚构测试文本，不含真实用户文档。全套 230 项自动测试、TypeScript/Vite 生产构建和 oxlint 通过；本次未进行浏览器端到端自动化验收。
