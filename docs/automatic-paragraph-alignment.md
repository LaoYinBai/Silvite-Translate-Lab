# 翻译完成后的中英段落对照

2026-11-07。现有翻译结果生成完成后，在浏览器 Worker 自动整理只读的段落对应关系，仅对 `zh → en` 或 `en → zh` 启用，兼容 `zh-CN` / `en-US` 等语言代码。其他语言不启动此流程。

## 数据与生命周期

- 普通文字和文档使用发起本次翻译时的原文快照；结果生成后修改输入框不改变旧结果的原文。
- 图片只有在响应含有实际识别原文时才有材料可对照；当前扫描 PDF 聚合结果没有完整识别原文时不伪造对应。
- 长文流程在每个确认请求、超时拆分后的成功请求和代码块直通时记录两侧字符范围。失败或取消的请求不生成锚点。
- 成品译文先显示，再启动对齐 Worker。新建翻译、重译或切换演示会取消旧任务；对齐失败仍保留完整译文，结果不改成翻译失败。

## 对应方法与边界

从原始字符串划分段落：优先空行分段，没有空行时按换行分段，代码围栏内部换行不单独拆分。保存原始 UTF-16 字符范围，保留分隔空白，不重写原文或译文。

先用已确认的长文请求边界约束对应区间；请求切在段落中间时不把该边界当作完整段落锚点。区间内以长度比例、数字一致性和顺序做有界动态规划，支持 1:1、1:N、N:1、N:M（自动每侧最多 3 段）和单侧未匹配。该思路采用基于长度线索的对齐方法，参考 [Gale 与 Church 的原论文](https://aclanthology.org/J93-1004/)，本实现是独立的段落启发式，并未复现该论文的概率模型。

它提供结构对应建议，不验证翻译语义，不承诺发现所有漏译、换序或错译。界面提示核对含义，拆合段、较弱对应和未匹配记录进一步标注；没有把代价换算成正确概率或自动标为人工确认。

两侧原文字符必须各覆盖一次；覆盖不完整时退出对照并保留完整译文。大规模行数或无法建立有界路径时，两侧段落均单独保留为未匹配。计算在 Worker，限制动态规划搜索带宽；20 秒未完成则释放 Worker 并保留完整译文。

## 界面与导出

- 默认显示“中英段落对照”，可切换“完整译文”；桌面两列，手机每组先原文后译文。
- 每页最多显示 40 组，长文本通过分页查看，所有组均保留在结果数据中。
- 复制和 PDF / Word / Markdown 继续只使用 `result.translation`；翻译说明仍由现有导出选项控制。
- 这项只读结果预对齐独立于专业语料工具的双文档导入、语义对齐、人工编辑与 TMX/RTF/SDLTM 互转；后者继续按原开工审查推进，不将本次功能标为完整语料工具已交付。

本次不添加依赖，不增加模型请求；代码入口在 `src/services/alignment/`、文档聚合、翻译 store 和结果组件。
