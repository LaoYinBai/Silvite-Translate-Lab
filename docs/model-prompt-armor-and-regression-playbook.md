# 多模态模型"破甲"与回归测试模板

来源：Silvite Translate Lab 漫画模式排序修复（mimo-v2.5，2026-09）。目标：把这次踩坑中**被实测验证有效**的提示词技术与**测试方法论**沉淀成可复用模板，迁移到其他模型 / 其他任务时按此清单操作。

---

## 一、问题背景（为什么要破甲）

任务：让多模态模型输出"真实阅读顺序"的结构化漫画 segments（panel / order / speaker / type），而不是按 OCR 空间顺序平铺。

模型默认行为（"甲"）：

1. **空间先验极强**：同侧多个气泡按空间连读，语义关系被忽略（约 50% 概率把"回应"排到"质疑"之前）。
2. **抽象规则执行力差**：写了"必须检查问答关系"，模型确认理解，但输出时不执行。
3. **规则过度服从**：给了硬规则又会在别的样本上过矫正（把质疑句提前到一切之前）。
4. **自洽的错误**：错误输出内部逻辑自洽（它给错误顺序写了合理化理由），事后 prompt 无法靠"再强调"解决。

结论：**单靠自然语言规则无法稳定收敛**（实测 ~50% 正确率天花板），必须组合"提示词定位 + 结构化补丁 + 代码确定性兜底"。

---

## 二、破甲技术清单（按实测效果排序）

### 2.1 规则写进 schema 字段描述里（★★★★★ 最有效）

把硬规则嵌入 JSON schema 对应字段的说明，而不是单独成段。模型在**生成该字段的瞬间**会读到它。

```json
"order": "全局真实阅读顺序，从 1 开始递增。硬规则：回应永远排在它所回应的句子
之后，即使回应的气泡在画面上更靠右或更靠下；质疑句若本身是对前句（解释/致歉）
的回应，也仍须排在该句之后"
```

对比：同样的话写在正文 bullet 里 adherence ~50%；写进字段描述后明显提升。
**模板**：每条硬规则都问一句"这条规则在生成哪个字段时最该被想起？"，把规则塞进那个字段的 description。

### 2.2 结构化补丁：让模型声明依赖，代码强制执行（★★★★★）

抽象语义 → 显式结构。让模型给每个元素分配 `id`，用 `reply_to` 声明"我在回应谁"，代码只执行声明：

```
约束：若 A.reply_to = B.id，则 order(A) > order(B)；违反则交换两者 order。
```

这是把"模型猜语义"变成"模型声明语义 + 代码执行声明"。声明方向错时无解（见 2.8），但声明正确时 **100% 确定性**。

**模板**：任何"X 必须在 Y 之后"类需求，优先设计成 `id` + `depends_on/reply_to` 字段，代码做拓扑修正，而不是让模型直接输出最终顺序。

### 2.3 可证伪的不变量检查（★★★★☆）

"请检查对话连贯性"这类模糊指令无效；**可判定的反例条件**有效：

> 悬空检查：若排序结果以未获回应的问句/质疑句收尾，几乎总是排错了——把在语义上回应它的陈述句移到质疑之后。

**模板**：把领域常识写成"如果出现 <可检测的异常形态>，则 <确定动作>"。异常形态必须能在输出里直接看出来（如"最后一句是问句"），动作必须具体（如"交换这两条 order"）。

### 2.4 表面线索启发式（★★★★☆）

把语用推理降维成模型可直接执行的表面模式：

> 词语回声线索：回应句往往复现它所回应句子的关键词——「为什么」→「因为」、「真的吗？」→「是真的」。含问号的句子与包含其关键词的陈述句并存时，问句在前。

**模板**：找出任务里"人脑靠语感判断"的点，写出它的**表面特征**（词形、标点、复现词），让模型做模式匹配而不是语用推理。

### 2.5 WRONG → RIGHT 对比例（★★★★☆）

给一个具体的小例子，同时展示错误排序和正确排序：

> 示例：三个气泡——甲「对不起，被老师叫住了。」、甲「今天是真的。」、乙「真的吗？」。
> 错误：对不起 → 今天是真的 → 真的吗（按空间连读）。
> 正确：对不起 → 真的吗 → 今天是真的（"今天是真的"回应"真的吗"）。

**模板**：错误示例必须**长得像真实失败案例**（同样的拓扑、不同的文本），并显式标注"错误"和"正确"两条链。

### 2.6 证据优先级链（★★★☆☆）

模型会抓错信号。显式给出权重顺序，并把最容易误导它的信号**显式压到最低**：

> 证据优先级：回应语义关系 > 问答关系 > 质疑/辩解关系 > 气泡尾巴归属 > 画格视觉流 > 阅读方向 > speaker 是否交替（最低权重参考，绝不能为了它强行改序）。

**模板**：列出任务中所有可用信号，按真实重要性排序，特别标注"哪个信号看起来可靠其实会误导"。

### 2.7 软信号框定，硬规则仅限可证伪项（★★★☆☆）

容易过拟合的信号写成"复核触发器"，不写成排序规则：

> 同一说话人连续出现多个气泡时，不要自动改序……仅把这当作对话连贯性复核的信号……若两句本身确实连续，必须保持同一说话人连续。

**模板**：写每条规则前先问"这条规则有没有反例？"——有反例的写成软信号（"触发复核"），没有反例的才写成硬规则。

### 2.8 已知残留缺陷（破甲不彻底处）

- **声明方向错**：模型偶尔把依赖方向写反（把质疑声明为对回应的回应）。代码无法在不猜语义的前提下纠正。
- **互为 reply_to**：模型输出过 A.reply_to=B 且 B.reply_to=A 的矛盾声明。代码侧解法：每个无序对只执行一次，**优先执行被违反的那条**（它是对抗空间先验的刻意声明，被满足的那条只是空间顺序的镜像）。
- **上游波动**：偶发空响应（~1/10，重试即可）、偶发把整个 JSON 双重编码塞进 translation 字段（代码解包防御）。

## 三、已验证无效 / 反效果的做法（负面结果）

| 做法 | 结果 |
| --- | --- |
| 长篇抽象规则堆 system prompt | ~50% 天花板，加更多条也不涨 |
| 降低 temperature (0.3→0.1) + 精简指令 | 更差：过矫正（质疑被提前到一切之前） |
| "两人轮流说话"硬规则 | 用户否决（真实漫画存在合法的连续同角色），且实测不稳定 |
| 事后重复强调同一规则 | 无效，模型错误自洽 |
| 复杂 responsive class 复用同一套 DOM | 可读性崩坏（前端侧同构教训） |

## 四、回归测试模板

### 4.1 机器判定，不靠人眼

写 verdict 脚本：断言相对顺序（`order(a) < order(b) < ...`）、断言不变量（环境文字不混入对白）、断言格式（主译文含结构标签）。输出一行 JSON PASS/FAIL。**人眼看 CJK 日志必然误判。**

```json
{"verdict":"PASS","orders":{"a":3,"b":4,"c":5,"d":6},"envInDialogue":false,"labels":true}
```

### 4.2 对照组防过拟合（必须）

每修一个失败模式，至少补两个反例对照：

| 对照 | 目的 |
| --- | --- |
| 同角色连续两句**确实合理**的样本 | 防止修复把合法连续强行重排 |
| 最简问答样本 | 防止基础能力被新规则破坏 |
| 与主样本同拓扑但不同文本的样本 | 验证修复是模式级的，不是样本级的 |

合成样本可行：SVG 画气泡/人物/尾巴 → sharp 转 PNG（本项目 `scripts` 有先例）。**画完必须人眼检查渲染**再送测。

### 4.3 稳定度用批次说话

单次 PASS 是运气。每轮改动后同输入跑 N≥3-4 次，报正确率；正确率 <3/4 视为未收敛，继续迭代或降级为"已知不稳定"。

### 4.4 原始响应留痕

verdict 脚本同时把 raw response 追加写进 jsonl。失败分类全靠它——本 session 的关键发现（互为 reply_to、双重编码、方向反写）全部来自原始日志，不是从最终输出看出来的。

### 4.5 失败模式分类表（本 session 实测）

| 失败模式 | 现象 | 归属 |
| --- | --- | --- |
| 空间翻转 | 同侧气泡连读，回应排在质疑前 | 模型默认行为 |
| 过矫正 | 质疑被提到一切之前 | 规则过强 / temperature |
| 方向反写 | reply_to 指错对象 | 模型声明错误，代码不可救 |
| 互为 reply_to | A↔B 互相声明 | 代码需配对去重 + 违反者优先 |
| 空响应 | 上游偶发 | 重试 |
| 双重编码 | JSON 塞进 translation 字符串 | 代码解包 |
| order 缺失/为 0 | 环境文字 order=0 | 代码回退到数组原序 |

### 4.6 职责边界（最终收口声明）

> 模型：看图、分结构、判语义、声明依赖（id/reply_to）、给初版 order。
> 代码：验证结构、执行声明约束、确定性渲染、fallback。
> **代码不猜语义，模型不负责最终排版稳定性。**

## 五、迁移到其他模型/任务的检查单

1. 需求里所有"必须 X 在 Y 前"→ 能否改成 `id` + 依赖字段 + 代码拓扑执行？
2. 每条硬规则 → 有没有反例？有反例的降级为软信号。
3. 每条硬规则 → 它在生成哪个字段时最该被想起？塞进那个字段的 schema description。
4. 领域语感点 → 能否降维成表面模式（词形/标点/复现）？
5. 写一个 WRONG→RIGHT 对比例，拓扑贴近真实失败案例。
6. 列证据优先级链，显式压制最误导的信号。
7. 写至少 3 个对照样本（含一个"修复不能破坏"的反例）。
8. verdict 脚本 + raw 留痕 + N 次批次，报正确率不报单次。
9. 代码兜底链：结构执行 → fallback 到模型自由输出 → 错误态，任何结构失败都不能导致空结果。
