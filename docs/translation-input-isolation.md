# 翻译输入隔离

2026-11-06。翻译站只处理翻译任务；待译材料里的请求、问题、角色声明、代码和命令均是原文，不成为模型的新任务。

## 请求边界

- 普通翻译的 system 消息仅由应用自有规则、固定模式和布尔设置组成。用户正文、Context 和 Terminology 不拼入 system。
- 用户消息使用 JSON 数据封装，明确区分 `source_text`、`user_context` 和 `glossary`。JSON 转义保证解析后原文完整；尖括号转义防止正文伪造外层标签。
- 上下文只用于消歧；术语只用于原文对应位置的译名，不能覆盖翻译任务、语言路由或输出结构。图片文字、扫描 PDF 页面同样受此限制。
- 同传把当前转写、上下文、术语、会话摘要和最近已确认语段都作为 JSON 数据，历史译文也不能引入新指令。
- 数据区前后重复应用自有的翻译任务和输出约束，避免兼容网关对长 system 提示处理不一致时，把用户资料当成普通聊天任务。
- 普通翻译保留现有结构解析、修复和不完整输出检查；不接受纯文本聊天作为成功译文，格式异常重试后报错。同传保留流式事件及完成状态检查。模型请求不附带执行工具。

## 验证范围

现有回归覆盖两个供应商的正文与参考资料隔离、伪闭合标签的无损编码、图片参考资料隔离和同传上下文隔离。模拟上游只能证明请求构造正确，不能证明模型必然遵守。发布后还需用真实模型验证含指令的材料仍被翻译。

`77f4e07` 发布后已用正式站实际检查两个模型：正文中的问题与命令正常被译出，Context / Terminology 伪指令未改变译文，同传摘要和历史伪指令未改变当前语段翻译。GLM 参考资料样本一次上游失败，相同请求重试通过。详情见 [模型验证记录](research/2026-11-06-model-provider-verification.md)。

这是降低提示词注入风险的分层措施，不能保证所有模型及所有攻击输入都无法越界。不要用关键词封禁或删掉待译句子来代替翻译。
