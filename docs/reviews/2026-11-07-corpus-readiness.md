# 中英对齐与格式转换开工审查

审查日期：2026-11-07。基线：`1a1e2bd`。本次审查方案、源码、原技术文档及真实样本，未实现转换业务、未安装依赖、未执行浏览器转换或 Trados 原生验收。

## 结论

**有条件可以开工：先做技术验证和统一数据模型，再进入格式适配与对齐。原方案不宜直接按 Task 1 → Task 6 顺序一路实施。**

技术方向及个人学生使用场景已经明确，基础模型、编辑器、TMX、样本式双栏 RTF 和 SDLTM 读取均可分步建设。完整的三格式互转尚未证明技术闭环，特别是任意新文本的 SDLTM 原生检索能力。不能把该问题留到所有界面完成后才验证。

## 发现与修订要求

### P1：模型不足以约束拆合句后的字符与标签保真

原方案 `UnitSide` 只有 `text`、`segmentIds` 和不透明的 `originalMarkup`；`StructuredDocument` 没有字符范围、原始块或匹配用文本的区分。编辑后原 XML 与新正文不一致时，适配器不知道该保留哪一份，也无法证明拆分、合并没有漏掉空白或标点。

现有 `fileParser.ts` 的 DOCX 路径先转 HTML，再去标签；PDF 路径删除重复页边和部分数字行；`officeParser.ts` 只返回 `plainText()`；统一归一化还会改写部分 Unicode 字符。这些选择适合当前翻译入口，不能直接作为专业语料保真层。

开工契约：

- 保存不可变的文档原始块，包含文档 ID、块 ID、原始文本、顺序及段落/表格/单元格路径。正文空白、换行、编号、重复段落不因匹配而删除。
- 每个句段引用原块的 `[start, end)` **UTF-16 code unit** 范围，与 JS 字符串切片一致；UTF-8 字节长度另计。匹配归一化只生成 `matchText`，导出使用原始内容或用户明确编辑的内容。
- 可编辑侧保存有序文本/内联标签节点；已支持标签保留名称、属性、成对标识及顺序。修改带标签内容必须更新节点和 revision，不得继续写出旧 `originalMarkup`；无法安全编辑的标签应采用受保护占位或阻止该操作并说明。
- 覆盖检查使用原始字符范围：每个非排除范围恰好属于一个已配对或未配对记录。重复句靠位置和 ID 区分；显式排除须有记录且可恢复。
- 编辑内容与原始材料分别保留。撤销/重做恢复文本、标签、范围、顺序和复核状态；修改过或重新对齐的记录重置为待复核。
- 自定义属性保留类型、作用域和原始值；int64 在 Worker 内用 BigInt，项目 JSON 用带类型的十进制字符串编码，禁止隐式转 Number。多语言 TU 的非工作语言变体也保留在项目中。

### P1：专业对齐没有可判定的质量门槛

原 Task 4 写了“比较准确性、耗时、内存”，但没有固定分句、质量计算、最大转移、长句策略和放行阈值。所有真实样本都来自同一类报告，不能代表课程中的商务、学术、叙事、表格等材料。只比较 TU 数或译文大致相似也不能证明对齐正确。

开工契约：

- 先定义中英文句界规则：标题、列表、表格和段落是独立块；覆盖 `Dr.`、`e.g.`、小数、序号、引号和中英文混排。分句必须保留空白，跨句标签不能因切分损坏。
- 自动路径至少覆盖 1:1、1:2、2:1、2:2、1:0、0:1；自动合并上限初始为每侧 3 句，禁止生成新的 0:0 路径。更大的对应可手工合并，导入时原有双空 TU 仍保留。
- 锚点以稳定范围/句段 ID 表示，锁定后重跑只处理锚点之间区间。重复、重叠、交叉锚点先诊断；单调算法不能恢复的换序进入人工移动/重新配对，不通过强行匹配掩盖。
- 句向量使用明确的 pooling、归一化、模型 revision 和 token 上限；超长内容切窗并聚合窗口结果，保存完整原文和窗口覆盖，不让 tokenizer 的截断替代句段处理。底模卡的推荐长度为 128，而转换仓 tokenizer 配置为 512，不能混用默认值。[E3][E4]
- 基准集至少包含 4 类合成材料（报告、商务、学术、叙事），合计不少于 240 个标注对齐组；含漏句、重复、2:2、长句及换序。开发集与保留评估集按文档隔离，不能在同一批样本上调参又报告最终质量。
- 以两侧原始范围集合的精确相等计算对齐组 precision / recall / F1，同时单独报告空对应、各类多句对应、错配和人工改动率。初始候选门槛定为保留集 F1 ≥ 0.90、字符覆盖 100%、锁定锚点违反数 0；这是工程目标，尚无实测结果，不能作为承诺任意文档准确率的依据。
- 原始评分只用于排序复核队列，不显示成正确概率；自动结果统一为待复核。用户确认后才成为已复核交付单元，允许带明确状态导出草稿。

### P1：重要依赖的浏览器验证放得太晚

RTF 核心和对齐算法仍是备选，SQLite 也只有文档可行性。候选源码不能直接等同于可打包浏览器库。Maxprograms TMReader 使用 Node 文件系统和 SQLite；Pandoc 3.13 浏览器包装默认从 CDN 导入 WASI shim，并加载相对路径 WASM；这些都需要具体适配。[E1][E2]

在 Task 1 的完整界面之前增加 Task 0，输出：

- 固定的 XML 方案：Worker 环境可用，按顺序保留混合内容，禁止外部实体/DTD 解析与外部资源加载；或者主线程限量解析后仅传可克隆结构。不能依赖 Worker 内不存在的 DOMParser，也不能用 `textContent` 抹平 TMX 标签。
- 固定版本的 RTF 解析路径，证明当前五组样本、`\uN`/`\ucN`、非 Unicode code page、行列重复定义、单元格换行、隐藏源文检测可得到正确结构。旧 Trados RTF 未有足够样本时先识别并明确限制，不声称通用兼容。
- 固定版本的 SQLite WASM，真实浏览器 Worker 内导入小库，绑定和读取超过安全整数的 int64，再导出回读；不以本机 Node SQLite 代验。SQLite 官方提供字节导入/导出与 BigInt API，但具体构建仍需验证。[E5]
- 复用已锁定的 `@huggingface/transformers@3.8.1` 做语义路线技术验证；Hunalign 只有在分词、词典及分发许可落实后才进入对比。不得把缺词典的 Hunalign 结果当作最终质量结论。
- 资源清单保存精确版本/revision、各文件 SHA-256、字节数、来源与声明；检查 WASM 解压后的大小及自托管加载。Pandoc 官方 WASM ZIP 是压缩包，16.2 MB 的下载大小不能推定解压后每文件都满足站点限制。[E6]
- 核心、npm 包装、代码、转换权重和字典分别记录许可。注册表本次返回 `@sqlite.org/sqlite-wasm@3.54.1-build1` 声明 Apache-2.0，而 SQLite 核心文档另有版权声明；不把两者当成同一分发项。[E7]

### P1：SDLTM 写出仍缺新内容的有效派生数据路线

此项是原方案已经诚实记录、但整体排期仍需前移的风险。技术文档所用占位 hash 及空 fuzzy 数据只能证明结构/第三方可读；现有 20 表样本也不能提供任意新文本的算法。

Task 0 即建立最小实验：使用全新文本，在临时副本上检查 hash、token BLOB、签名、fuzzy 数据与关联关系的可生成条件；进入正式出口前必须通过原生打开、精确/模糊查询、编辑保存、重新打开及 TMX 回导。内容来源和验证步骤要能复现；不得修改用户的原库，也不得复制旧 TU 的派生值用于新文本。

实验尚未通过时，可继续完成其他模块，但“纯浏览器完整三格式互转”的状态必须为未完成。用户原始目标保持不变，不能擅自将 TMX/RTF 替代品当成 SDLTM 需求已交付。

### P2：格式损失、持久化、性能和离线范围需固定

- TMX 默认写出 1.4b；按实际 `xml:lang` 选择工作语言，保留 locale 与原 header；header 冲突由用户确认。不能将选出的两种语言悄悄替代原 TU 的其他变体。
- 统一导出前损失清单：RTF 表格不能等同于 TMX/SDLTM 全部元数据及内联标签，复杂结构降级必须列出受影响单元，用户可取消。所有导出来自同一份当前快照；本项目的双语 RTF/TMX/SDLTM 与翻译页的“仅译文 PDF/Word/Markdown”是不同交付物。
- 输入文件及解析展开量分开限额，避免小 ZIP/RTF 产生大量结构；先在移动端以每文件 10 MiB、每侧 100,000 字符和 2,000 个初分句作为技术验证工作负载，PC 以每文件 25 MiB、每侧 250,000 字符和 5,000 个初分句作为验证工作负载。这些是拟验证规模，不是已支持上限。
- 动态规划按锚点、块和带宽限制内存，不建立无界的全量稠密相似度矩阵；表格使用窗口化显示。资源下载与推理分别显示进度，收到取消后 1 秒内停止本任务状态更新，旧 jobId 不覆盖新会话；确有同步 WASM 计算时终止并重建 Worker。
- 先测 100/500/2,000 句的运行时间、峰值/可观测内存和两次连续运行；写出测试设备与浏览器版本。浏览器不能提供统一内存指标时如实记录测量方法，不伪造数值；手机达不到预算则给可处理规模与手工模式，不伪称自动模式全部可用。
- 项目 JSON 保存 schema 版本、原始结构、当前内容、顺序、语言、标签、编辑和复核状态；原始文件可另存本地引用，但不能把仅持有的 File 对象当作可跨刷新恢复的数据。自动保存用 IndexedDB；配额失败明确提示并允许手动下载项目，不能静默丢失编辑。
- 第一阶段离线定义为“本次页面与所需资源加载完成后，断网仍能导入/对齐/编辑/导出”；离线关闭浏览器再打开站点另需应用壳缓存，本轮源码没有该验收证据，不混为一个承诺。
- 修正 store 路径为现有项目风格 `src/store/corpusStore.ts`，避免另起 `src/stores/`。

## 放行顺序

1. **现在可开工**：Task 0 可行性验证、原文保真模型、合成夹具和项目格式。Task 0 分通道记录结果，某个出口未通过不阻塞互不依赖的基础工作。
2. **进入端到端实现前**：XML/RTF/SQLite 路径完成最小浏览器证据，数据契约与对齐评估集固定；分别接入 TMX/RTF、SDLTM 读取和语义对齐。
3. **对外标为专业可用前**：满足覆盖与质量门槛、可恢复人工审校、交叉格式检查和 PC/手机实测。
4. **对外标为完整互转前**：SDLTM 派生数据及原生关卡通过；否则整个原始目标仍有明确未完成项。

本轮已将以上约束及 Task 0 入口补入原实施计划。没有因审查把实现任务勾选为完成。
