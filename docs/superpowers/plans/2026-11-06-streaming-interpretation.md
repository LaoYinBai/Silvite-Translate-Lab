# 流式双语字幕实施计划

依据：`docs/research/2026-11-06-streaming-interpretation.md`；用户已批准按社区方案实施。

目标：浏览器 Whisper 持续转写，文字翻译独立排队；显示可修订草稿，按语段确认译文。

## 约束

- 沿用 Whisper Worker 与 MiMo 翻译，不引入本机服务或大型翻译模型。
- 手机继续默认 CPU；“仅转文字”不发送识别文字或音频。
- 以 utteranceId 标识语段，revision 标识源文版本，requestId 隔离生成与重试。
- 一次只运行一个翻译任务，合并草稿快照，保留所有句末任务；限速必须末次执行。
- 翻译失败保留源文和可见草稿，支持句段重试；翻译状态不阻塞 ASR。
- 停顿、句末标点、停止和有界长语段触发源文确认；上下文只使用之前的语段。
- 本轮不接入 TTS，不部署或推送。

## 实施步骤

1. 整理实时翻译服务端 SSE：start/delta/final/error，身份回显、完整结束检查、取消和超时。
2. 客户端解析跨包 UTF-8、SSE 帧、修订及请求标识；重试清空本轮草稿，断流不确认。
3. 独立翻译调度器：一个在途任务、每句一个最新草稿、按序保留的 final、末次节流。
4. 会话接入：稳定句段 ID、源文修订、上下文、标点/静音/长段确认、识别与翻译错误隔离。
5. 字幕 UI：草稿、排队、生成中、确认和失败，句段重试；保留响应式布局与触控尺寸。
6. 类型检查、构建、lint 和差异审阅；同步架构与开发记录。真实 MiMo/手机性能的未验证项明确记录。

## 审阅重点

- 慢翻译或失败时后续 ASR 可继续消费。
- 句末任务不会被新草稿或重试覆盖，迟到事件不能更新其他语段。
- 暂停/停止/卸载、模型加载取消、断网重试和重新开始时无跨会话更新。
- 原文持续增长受到长度与时间上限约束；已确认边界附近的音频重叠不重复追加。
- 上游 length、异常 EOF、非文本输出及取消不会伪装成成功 final。

## 实施进度

- 步骤 1–5：已完成本地代码，协议、独立队列、语段状态和响应式字幕界面已接通。
- 步骤 6：TypeScript、Whisper 静态准备、生产构建、oxlint、JS 语法及 diff 格式检查通过。
- 独立审阅：发现启动取消设置同步、暂停代次、有效草稿保留三项问题，已修复；另修复当前草稿被旧句重试打断后未恢复的问题。
- 决定：遵循当前会话的开发指令，本轮不新增或运行自动测试；已有 handler 测试仅迁移协议预期，构建检查不等同于运行验收。
- 真实 MiMo、浏览器收音和 iOS/Android 真机未在本轮联调；此前 Whisper/格式转换整体正确性不在本轮静态审阅范围。
- 没有提交、推送或部署。详细交付边界见 `docs/realtime-streaming.md`。
