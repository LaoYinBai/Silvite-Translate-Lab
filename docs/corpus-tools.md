# 中英语料工具：TMX、RTF、SDLTM 实验输出与双文档对齐

2026-11-07。入口为侧栏「中英语料工具」，手机从「菜单」进入。TMX / 常见双栏 RTF 的读写、互转，以及中文和英文文档的可校正对齐已接入 Beta。**TMX → SDLTM 实验输出**已接入严格哈希、Token 与双向模糊特征，通过本地 WASM、原生 Token 读取及桌面/移动视口浏览器导出检查；真实手机和 Trados 完整使用流程仍待验收。

默认打开双文档对齐流程，以学生在电脑上完成翻译作业为主要使用场景：选择两份中英材料、选择方向、自动对齐、人工校正并导出，不要求安装转换软件。后续的一站式学习工具围绕同一份材料衔接翻译、术语整理、语音和成果导出；不在本轮把未实现能力标为完成。

## 使用流程

### 已有双语文件

在「格式转换」导入 TMX 或双栏 RTF，检查方向和对应行，校正后导出。TMX 按实际 xml:lang 识别语言：显式选项优先；未指定时，使用有效的中英 header `srclang` 决定源方向；没有可用的中英 header 时默认中文 → 英文。其他语言变体留在项目和 TMX 中，正文不因选方向而改写，界面可交换中英方向。RTF 按用户指定的左右列语言导入，不能靠字体猜语言。

输入与输出方向都可以自行选择：TMX 的「导入工作方向」提供自动、中文 → 英文、英文 → 中文；RTF 选择源文/左列语言；双文档对齐也有工作方向选项。已有项目在「当前项目工作方向」选择中 → 英或英 → 中，再导出 TMX、RTF 或实验 SDLTM。切换保留实际 locale 标签和双语正文，只调整工作侧及导出方向。

已有中英文翻译结果的段落对照区域提供「制作 TMX / RTF 语料」，一键带入本次原文快照、译文和段落关系。它们仍标为待复核，可继续人工编辑或重新语义对齐；复制和普通 PDF / Word / Markdown 导出保持只取译文的现有规则。

空源文、空译文和双空行保留，不自动补译、不自动去重。导入文件的已有行也先标为待复核。

### 两份中英文文档

分别选择中文与英文的 TXT / Markdown / DOCX / 普通单语 RTF，或直接粘贴正文；选择工作方向及算法后开始。Markdown 在本轮作为保留原字符的文本输入，不执行其中的链接或脚本。

- **本地语义对齐**：多语 MiniLM q8 句向量加有界动态规划，mean pooling、L2 归一化。分句及匹配只生成关系，不调用翻译 API、不生成或重写原文。
- **快速结构对齐**：免模型下载，以长度、数字和顺序生成初步关系，不判断翻译语义。
- 两种方式均支持 1:1、1:N、N:1、N:M，自动每侧最多 3 句，以及单侧未匹配。分句覆盖小数、常见英文缩写和中英句号；所有原字符范围保留。
- 模型推荐长度按 128 token 处理。长句显式切窗，逐窗取向量后按 token 数加权聚合，检查每窗重编码长度，不依赖静默截断。
- 锁定两侧都有来源的行作为锚点，再重新对齐。重跑保留锚点文本与 ID，替换其余行；交叉/重叠锚点报错。
- 原始算法分数不是正确概率，不自动确认任何对应。换序和错配通过人工操作处理。

### 人工校正与保存

编辑器提供单侧文字修改、行确认、相邻行合并、两侧分别指定位置拆分、右侧上/下移、任一侧独立成行、锚点、排除/恢复、添加空行及 20 步撤销/重做。分页每次显示 25 行，可按待复核、空侧、锚点或正文搜索筛选。

拆分按原始 UTF-16 范围执行，拒绝从代理对中间切开；修改过文字的单元须先撤销文字修改再拆分，避免伪造原始位置。含行内 XML 的单元通过专门编辑器校验，自动拆合会明确拒绝；保留标签顺序、配对和属性，不把旧 XML 套在新正文上。

TMX 的 TU 级元数据保留；TUV 元数据随单侧移动，不误用目标行旧译文的字段。合并涉及多条原始 TU 时，将原字段与片段保留到项目及 x-silvite-merged-original-units 属性，并提示其作用范围发生变化。

项目自动保存在当前浏览器 IndexedDB，可下载版本化的 `.corpus.json`，恢复原文块、范围、当前文本、内联标记、工作方向、人工校正、复核和排除记录。项目文件不保存原 DOCX 的二进制、原排版及撤销栈；原始文件不被覆盖。自动保存失败会提示下载项目，不静默视为成功。

### TMX → SDLTM 实验输出

在现有 TMX / RTF 与中英对齐流程之后，新增「导出 SDLTM（实验）」出口。导入 TMX 后确认中英工作方向、核对并编辑对应行，再查看损失清单并确认实验导出。输出遵从项目当前工作方向，使用当前未排除记录的工作中英文本，保留行序、空源文、空译文和双空记录；不以原始 TMX 快照覆盖用户已经保存的编辑。

- 工作中英侧含保护性行内标签或代码时，阻止本次 SDLTM 导出并定位相关记录；不通过剥离标签生成一个看似成功的文件。需要保留这类内容时使用项目 JSON 或 TMX。
- 其他语种变体、TU/TUV 自定义字段、notes、用户/时间信息及应用内复核、来源记录的未表示部分，须在导出前列入损失清单，由用户确认；完整内容仍保留在项目中。
- 导出界面及确认区域的小字须明确显示 **「不保证兼容 Trados」**。用户已授权实验输出，原生 Trados 尚未验证不再作为禁止输出的条件；这项授权不等于原生兼容或专业对齐质量已通过验收。
- 实现按逆向终稿的完整 DDL，在 SQLite WASM Worker 的空内存库中直接建库；随后写入记忆库、句段、Token 与模糊特征。从最终输出字节重新打开，检查 20 张业务表、25 个普通索引、数据库完整性、外键、计数、语言和逐行内容。检查失败须报错，不把损坏或缺行的结果作为成功文件交付。
- 已按 `sdltm-implementation-guide.md` 接入 Jenkins/FNV 严格哈希、`Intl.Segmenter` 中英分词、Snowball English 词干、双侧 Token BLOB，以及 `fi1/fi2/fi4/fi8` 模糊特征。`tokenization_sig_hash` 保留 NULL，需由 Trados 重建识别器、上下文、片段与词级对齐数据；不承诺重建前的匹配与原生引擎完全一致。
- Token 编码已修正指南示例中的字段问题：数量是 int16，跨度 Index 是 Segment 文本元素编号（此处为 0），单字符位为 `0x20`。超过紧凑格式的数量/位置/长度容量时写版本 1 的 int32 普通格式，不截断字段。Segment XML 不写 `LastElement`。UTF-16LE 明确按字节编码，Jenkins 高位按无符号 uint32 相加。
- 版本参数为 `VERSION=8.06`、`VERSION_CREATED=8.10`、`FREQUENCYTOP=1000`；两个 DataVersion 参数绑定当前 TM。未破解的 `fragment_hash` 不用 source_hash 充当，片段索引留待原生重建。数据库可回读仍不等于完整 Trados 使用流程通过验收。

## 格式支持与损失说明

| 格式 | 当前范围 | 明确边界 |
| --- | --- | --- |
| TMX | 1.4/1.4b 常用结构、实际语言标签、实体、bpt/ept/ph/it/hi/sub/ut、多语言变体、空 TU、TU/TUV 字段与 notes | 不支持的行内元素、内部实体/DTD、无效编码或结构报错；根/body 的额外属性及头/TU 外注释不能保留时有提示 |
| 双栏 RTF | 普通双列表格的逐行读写、Unicode、代码页、单元格换行、重复行定义、空行 | 复杂合并/嵌套表格、旧 Trados 隐藏源文、不能安全映射的对象报错；不承诺任意 RTF 的版式往返 |
| DOCX / 单语 RTF | Pandoc AST 中的段落、标题、列表、表格文本和位置 | 字体、装饰等不能还原时提示；无法安全提取的对象拒绝，PDF/OCR 不在当前入口支持范围 |
| SDLTM | 当前中英工作对的实验写出，包含哈希、Token 与四列模糊索引；支持双向导出 | 工作侧保护标签阻止导出；其他语言和元数据缺口列损失清单；原生识别器与片段索引待重建，**不保证兼容 Trados**；通用 SDLTM 导入另行实现 |
| 项目 JSON | 版本化的完整编辑数据、原始文本及校正状态 | 加载时校验结构、字符位置和内联 XML；不兼容的版本拒绝 |

导出前展示损失清单和待复核数量。RTF 只交付当前工作语言的双栏正文，其他语言、TMX 字段、行内标签和复核状态不会伪装为已保留；需要保留完整数据时另存项目。未全部复核的 TMX/RTF 文件名带「待复核」。

Pandoc 会规范化表格边界空白。因此本站导出的 RTF，在需要时附带合法、可忽略的 `silvitewhitespace` destination，只记录边界空白及当前正文校验值。本站回读时先核对正文与记录，再恢复 TMX 中原有的尾部空格、换行；其他软件改写后不盲用旧记录。该记录不包含外部指令，不用于鉴权，也不能保证任意第三方工具保留边界空白。

## 数据与运行边界

- 全部文件处理、格式转换、句向量推理、对齐、编辑和下载在浏览器完成。语料工具不调用聊天模型或转换后端；既有翻译站的健康检查不携带文档正文。
- 原文块不可变，当前编辑内容与原始文本分别保存。匹配文本的空白归一化/NFC 不写回原文。自动对齐及其后导出检查两侧每个原始范围恰好覆盖一次；被用户明确排除的记录仍保留在项目中。
- XML 使用页面线程的标准 DOMParser，输入有字节、节点和深度限额；拒绝内部实体，外部 DTD 仅安全移除且提示，不取外部资源。Pandoc 和模型重计算在 Worker，取消终止 Worker，旧任务不替换新项目。
- 输入单文件最大 10 MiB，项目最大 30 MiB；文本、原文块、单元数和 AST 展开量分别限制，对齐每侧最多 5,000 句。它们是代码保护上限，不表示所有手机都能承受上限工作负载。
- Pandoc 3.13 WASM 约 62.2 MB；MiniLM 模型加 tokenizer/config 约 135.4 MB，另有 ONNX 运行组件。只在对应流程按需加载，支持完整性校验和分片缓存。向量模型使用 CPU/WASM 单线程，WebGPU 不是运行条件。
- SDLTM 使用 `@sqlite.org/sqlite-wasm@3.54.1-build1`，生产实现为纯前端 Worker，不调用 Node 或转换后端。本机开发核验另用 Node 原生 SQLite 独立读取输出；这项开发工具不构成成品依赖。五份样本输出各约 0.5 MB，不表示手机性能或大文件上限已验收。
- 模型、解析器和 ONNX 运行组件均进入按 revision 管理的本地分片缓存；清单请求失败时可回退到已保存清单。运行组件校验后由本地 Blob URL 加载。缓存配额不可用时允许当次下载使用；离线与真实浏览器缓存行为仍需单独验收。
- 所有成品资源来自本站 `/corpus/`。构建时运行 `npm run prepare:corpus`，固定 Pandoc 归档/引擎哈希、模型 revision `2c4055b12046f11709e9df2c122e59ffbdc2f900` 及各资源 SHA-256；大权重/WASM 拆为最大 20,000,000 字节。运行组件单文件小于 25 MB。
- `predev` / `prebuild` 自动准备资源。构建需要访问模型与开源发布源；浏览器运行不直接取外部 CDN。首次资源加载完成后的当前页面可继续本地工作，不承诺离线关闭后重开网站。
- 开源组件、原始来源及许可随 `/corpus/` 发布：Pandoc GPL-2.0-or-later 及对应源码入口、WASI shim、Transformers.js、ONNX Runtime 与声明。底模声明 Apache-2.0；ONNX 转换仓未单独声明许可，保留底模声明和转换来源，不将其写成另有独立授权证明。

## SDLTM 实际证据与待验边界

以下保留初版结构写出的证据，开发日志为 `.cache/corpus/sdltm-replay.log`（本机缓存，不随仓库发布）。初版使用占位哈希，未运行浏览器端到端或原生 Trados 验收；当前算法和新增证据见下一节「终稿算法接入」。

- 用户技术文档的“真实空模板 + SQLite 注入 + Segment XML”是实现依据，见 [调研记录](research/2026-11-06-static-conversion-and-alignment.md)；其中的旧回读经验与下列本轮结果分开记录。
- 五组 TMX 的 header 为 `srclang=en-US`，提供的原生参考 SDLTM 却是 `zh-CN → en-US`。**本次样本比较显式选择原生库的 zh → en 工作方向**，不声称两类原文件天然同向；按 header 默认导入时会是 en → zh，用户可在界面反转。

| 组 | 输出 TU | 原生参考 TU | 输出字节 |
| --- | ---: | ---: | ---: |
| 9 | 42 | 41 | 516096 |
| 10 | 49 | 48 | 524288 |
| 19 | 30 | 30 | 507904 |
| 20 | 20 | 19 | 499712 |
| 25 | 42 | 42 | 516096 |
| 合计 | **183** | **180** | 五个独立文件 |

- 每条输出 Segment 由独立 DOM 提取正文和语言，再按所选工作方向与 TMX 逐字符核对，五组 `exact=true`；此比较不先 trim、不做 NFC 或换行归一化。SQLite WASM 写出及自回读后，Node 原生 SQLite 独立只读检查的 `integrity_check` 均为 `ok`、外键违规均为 0。
- 与原生参考库比较时，另行统一换行为 LF 并 trim；原生 **180 条全部保留**，额外三条为第 9 组第 42 条、第 20 组第 20 条双空，以及第 10 组第 20 条中文空、英文非空。最后一条的英文在这项归一化比较后为 121 字符；这不是 TMX 原始字段长度，不能据此裁剪输出。
- 从官方 13 表空模板出发，补齐样本 20 业务表、25 个显式普通 SQL 索引及新增列；表名/索引名集合与每份原生样本一致。清除模板自带的 2 个属性定义和 4 个 picklist 值，保持 `VERSION=8.06`，不伪称由 8.10 生成。未复制用户 token 数据，也未重建专有模糊检索索引。
- 固定 GUID 样例的 .NET `bytes_le` 布局与 signed int64 / BigInt 精确回读已核实，保护性 markup 的导出拒绝已回放。补充 3 条 `en-US → zh-CN` 反向记录，覆盖 CRLF、emoji、补充汉字、空侧和双空；实际浏览器胶水 `index.mjs` 与 SQLite WASM 在 Node 中初始化、禁用 OPFS（`opfs=false`），本地自回读通过。这不等于浏览器端到端或反向原生兼容验证。
- `.cache/corpus/direction-replay.log` 对第 19 组 30 条分别核对自动 header en → zh、显式 zh → en、显式 en → zh、手工反转 en → zh，四条路径均 TMX exact、RTF exact、SDLTM 本地自回读通过，locale 保留。翻译结果的 2 段带入项目也已通过范围覆盖回放；这些记录不是点击界面的浏览器验收。
- 同一工作语言出现多个变体（含大小写或下划线差异）时，SDLTM 导出会明确拒绝，避免忽略第二个变体及其保护标签；此拒绝路径已用重复 `en-US` / `EN-us` 的 TMX 回放核对。
- SQLite WASM 包固定为 `3.54.1-build1`；模板和引擎哈希、占位哈希规则见 [开发记录](../DEV.md)。20 表、25 个 SQL 索引及独立 SQLite 可读，仅证明上述结构与正文检查，不能证明 Trados 原生打开或检索可用。
- 待验项仍包括浏览器 Worker、文件选择/下载、IndexedDB、PC/手机端端到端、性能与断网证据、专业保留集 F1，以及 Trados 打开、精确/模糊检索、编辑保存和重开。实验输出无需等待原生 Trados 验收，继续明确显示「不保证兼容 Trados」。

## 终稿算法接入（2026-11-07）

`sdltm-implementation-guide.md` 是用户逆向 Trados Studio 后确认的格式基准。当前导出按该终稿及参考实现更新，使用站内 SQLite WASM Worker。完整 DDL 已归入 `src/services/corpus/sdltmSchema.sql`，来源为用户提供的 `analysis/out/CreateSchemaSQLite.sql`。生成流程直接执行 DDL 建立空数据库，不再下载 SDLTM 空模板或通过 ALTER TABLE 拼补旧模板。Snowball 依赖仅随 SDLTM Worker 加载，Node、SQLite CLI 和 Trados DLL 不参与网站运行。

## 构建核对（2026-11-07）

完整 `npm run build`（包括 ASR / 语料资源准备、TypeScript 和 Vite）、oxlint、Git 空白检查通过。语料资源清单含 13 个逻辑资源、21 个实际文件，共 231,552,268 字节，逐片及拼接 SHA-256 全部一致；整个发布目录的最大单文件为 21,596,019 字节，小于 25 MB 限制。静态资源准备不读取用户样本目录，发布包不包含私人语料或本机转换脚本。Vite 仍报告既有大 bundle 提示；语料界面和工作线程按需加载。

为保证首次构建不依赖 GitHub 匿名接口配额或本机缓存，已将官方 Pandoc 3.13 发布归档、压缩编码的公开 SDLTM 空模板及对应许可/运行时声明固定在 `scripts/assets/`，准备时仍验证原始哈希。模型继续按固定 revision/hash 获取。浏览器仅从本站按需加载生成资源，无需安装这些构建工具。
